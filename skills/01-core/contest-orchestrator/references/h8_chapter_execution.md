# H8 章节执行协议

Harness 控制记录启用 `visual_workflow: chapter_parallel` 时，先按 [逐章批准写作与并行图表](harness_chapter_parallel.md) 在 H6 获批后，由同一 H8 论文实例提交计划，并按 `writing_order` 一次完成一章。`chapter_order` 只规定最终读者/目录顺序。每一章的完整正文、质量审查和 `H7_CHAPTER:<chapter_id>` 用户批准是下一章派发的前提；图件并不是。章节批准后才可生成图表提示词，用户亲自转交 H7，图件制作或返修可与下一章写作并行。`writer_first_draft` 控制记录仍按 [初稿准备协议](harness_writer_preparation.md) 处理。正式 H8 和 H9 的所有门禁保留。

所有 H8B 写作先读取 [H8 写作者优先协议](h8_writer_first_protocol.md)。写作目标是形成读者可跟随的论证，不是把上游材料或任务卡字段按顺序转写。

全文以 `paper_narrative.global.paper_spine` 为唯一章节顺序。作者简报、章节卡和连续性包必须复用同一份 `paper_spine`，并为每章登记 `chapter_role`、`reads_from`、`feeds_to`、`new_claims_allowed` 和 `handoff_question`。`core` 章节集中承载建模与求解；`support` 章节只负责铺垫、连接、解释或收束。检查器会阻断章节顺序、角色、前后承接或允许主张不一致的写作任务。

## H8A：作者简报与写作计划

输入为题面、已核验的 `paper_narrative.yaml`、结果解释卡、素材准入、主张覆盖和已冻结证据。H8A 先读取并冻结 `global.paper_spine`，再把同一主线展开为作者简报和写作计划；每一章都要说明它承接的前置回答、允许新增的主张以及交给下一章的读者问题。在 `chapter_parallel` 中，计划必须另列最终 `chapter_order` 与实际 `writing_order`，核心建模/求解章节置于实际写作的依赖链前端，摘要只保留为正式 H8 的最终任务。初始计划不以正式图表或已闭合登记为前提。

`academic-writing` 先生成 `paper_argument_blueprint.yaml`、`paper_author_brief.yaml` 和 `abstract_argument_card.yaml`。摘要论证卡只规划摘要的读者契约、全文主张、统一建模主线、逐问方法—结果—意义、验证结论、总评和关键词，不写最终摘要正文；每个小问必须绑定可核验的冻结证据。作者简报的建模问题章节还必须登记 `chapter_kind`、问题引入段和双小节结构；每章保留读者问题、章节目的、章节回答、论证 ID、可用证据、图表职责、读者收获和排除材料。

主 agent 根据作者简报和摘要论证卡生成写作计划。作者简报、摘要论证卡和写作计划必须一并提交用户审查；摘要论证卡未批准不得开始正文。

## H8B：逐章写作

主 agent 每次从已批准的作者简报生成一个 `chapter_writing_card.yaml`，并更新一个 `paper_continuity_context.yaml`。两者必须携带并绑定同一 `paper_spine`，明确当前章节的角色、前后章节和 `handoff_question`。在 `chapter_parallel` 中只可派发 `writing_order` 的下一个依赖已满足章节；其草稿与 `quality_review` 必须绑定同一 SHA-256，并由用户以 `H7_CHAPTER:<chapter_id>` 批准后才可派发下一章。派发前依据当前冻结证据和章节适用性填写章节卡的 `abstract_contribution`；该字段供 H8C 汇总摘要，不能由 H8B 临时改写成摘要。任务派发后保持章节卡及其他哈希输入不变，论文 agent 回传摘要贡献的核对结果；发现与冻结证据或完成正文不一致时返回证据缺口，由主控按现有影响范围处理，不覆盖历史输入。论文 agent 只使用当前章节卡、连续性包、模型总结卡、摘要论证卡和卡内列出的冻结材料写当前章节。连续性包只保留中心主张、已完成章节收束、术语口径和前后章节衔接，不携带全部历史原始材料。

| 章节类型 | 取用材料 | 写作重心 |
|---|---|---|
| 摘要 | `abstract_argument_card.yaml`、正文定稿、结果解释卡、最终主张 | 仅由 H8C 在全文定稿后写作；按背景、总体方法、逐问方法与量化结果、验证与总评组织 |
| 问题分析、评价、结论 | 作者简报、结果解释卡、图表论证职责 | 回答读者问题并解释结论意义 |
| 建模与求解 | 当前章节卡、模型总结卡、对应推导/代码/结果/验证材料 | 先用不编号引入段说明问题，再分“模型建立”和“模型求解与结果分析”两节；最终模型框放在模型建立小节末尾 |
| 图表段落 | 当前章节卡、视觉论证计划、图表登记、题注 | 说明图表如何支持当前论点；计划外图表返回证据缺口 |
| 附录 | 附录计划与实际支撑材料 | 保留可复现细节，不重复正文论证 |

写作时先写论证，完成本章的读者回答和论证链后再进行硬性检查。每段只承担一个主要沟通任务，并用自然过渡连接前后段落；章节卡字段不得直接变成正文清单。不存在强制段落模板或固定长度配额。一级标题使用中文序号，模型假设与符号说明分设为两个全局一级章节；建模问题统一置于“模型建立与求解”一级章节下，每个问题先写不编号引入段，再使用“模型建立”和“模型求解与结果分析”两个编号小节。核心章节必须围绕建模与求解展开，支撑章节必须明确服务对象并回收至核心主张。任何章节缺少应有的推导、结果、验证、图表或引用依据，或无法完成前后章节承接时，返回 `evidence_gap_matrix.yaml`；不得以重复表述、泛泛背景、空洞评价或文献堆砌补足篇幅。若当前章 `visuals_required: false`，明确登记即可；若需要图，批准后才产生图表提示词。

## H8C：独立编辑

`chapter_parallel` 的正式 H8 整合派发使用同一已登记论文角色，任务卡可明确标注 `authoring_protocol.stage: H8C`。输入按最终 `chapter_order` 绑定已批准的逐章正文原路径和 SHA-256、原写作计划及最终图件登记；这些引用取自已通过当前逐章闭合检查的现有记录，不复制正文或补造批准。另绑定当前作者简报、摘要论证卡、模型卡和视觉计划。H8C 仍须符合完整 H6/H7、H8 审查及 H9 门禁；历史 H8B 任务卡按原规则读取。

为保留各章的 `abstract_contribution`，逐章写作时应保留独立章节卡，并在既有 `nodes.H8.chapter_writing_cards` 登记。正式 H8C 的 `inputs` 引用每个获批非摘要章节对应的登记卡原路径和当前 SHA-256；如某章材料缺失，返回缺口，不根据其他章节补造。既有章节卡内容与证据检查仍然执行，这些引用不构成额外的人为批准。

作者简报和论文主线共同认定的非建模支撑章节，确实没有独立摘要主张时，可在 `abstract_contribution` 中登记 `status: not_applicable` 和具体 `reason`，不再填方法、结果、意义或证据；不能同时填贡献内容。建模章节以及实际有摘要贡献的支撑章节仍须填写完整方法、结果、意义与证据。此声明不代替章节批准或最终摘要检查。

当前完整闭合检查通过时，Harness 检查报告的 `h8c_handoff` 给出原计划、最终图件登记以及按阅读顺序排列的获批章节路径与哈希，可据此填充整合任务卡。该字段仅描述逐章交接证据，不代表整个 Harness 检查通过，也不替代 H8/H9 的人工批准或交付检查。

其中 `chapter_cards` 仅列出已登记且路径、哈希与对应章节写作派发输入一致的章节卡，可复用其路径和哈希填充 H8C 输入。`unverified_chapter_card_ids` 列出无法由现有记录确认该对应关系的章节，不推定文件不存在或人员违规；此信息不改变历史逐章闭合结果，章节卡内容和正式 H8 其余门禁仍须分别检查。

H8C 延用最后一章的写作连续性包时，`completed_chapters` 按已批准计划的 `writing_order` 判断先后；`paper_spine.chapter_order` 仍用于最终读者顺序与章节衔接。只有本次完整逐章闭合返回的原计划可用于此判断；历史 H8B 和其他流程保留原规则。

`chapter_parallel` 进入正式 H8 时，计划路径及哈希复用已批准的逐章原计划，人工批准登记保持真实。检查器消费本次完整逐章检查返回的来源，原计划及历史批准不回写；不要求另造旧格式的 `sections` 或页数配额。未完成图件闭合、来源变化或批准缺失时仍阻断；旧格式计划继续按原规则校验，实际页数限制留在正式交付检查中。

`academic-writing` 在正文与附录定稿、H7 最终图件闭合后先按 `chapter_order` 通读全文，整合已选图件，检查章节递进、过渡、主张回收和结论力度，再独立核验“作者简报—已批准正文—冻结证据”的对应关系。它只做图前图后解释、图注、排版与必要局部编辑，不从头重写已批准正文。随后依据 `abstract_argument_card.yaml` 汇总各章节的 `abstract_contribution`，最后写摘要；摘要必须运行 `scripts/check_abstract_contract.py --strict`，并登记 `abstract_contract_report` 及当前摘要论证卡 SHA-256。报告未通过或未绑定当前摘要论证卡时，H8C 不得完成。

H8C 还必须逐项核对 `paper_spine`：核心章节是否构成建模与求解的连续主轴，支撑章节是否只提供必要服务，每个章节是否回答当前读者问题并完成 `handoff_question`，正文是否出现孤立章节或章节间断裂。发现结构断点时回流作者简报或章节卡；发现证据不足时回流对应产物节点。

摘要闭合报告必须明确 `strict: true`、`passed: true` 并绑定当前摘要论证卡哈希。非严格检查即使返回 `passed: true` 也不能作为闭合依据；严格检查中的数字密度等诊断 `WARN` 仍允许，不因此额外重跑或增加人工批准。

- 证据不足：返回具体证据缺口和责任节点；不要求作者补写空泛文本。
- 表达或组织问题：生成受保护的局部正文补丁。
- 公式、数字、引用、图表、模型逻辑和冻结结构不得改动。

成稿必须移除元话语、内部交流和负向回声，只保留面向评阅者的论证、证据、结果与结论。
